# 시안을 그리는 절차

`/design` 으로 불려 왔을 것이다. **이 절차는 사용자가 부를 때만 시작된다.**

`/task` 의 트리거 넷은 관찰이라 자동으로 걸리지만, 시안은 다르다.
「그림으로 봐야 정해지는 것」이 있는지는 만들자고 한 사람이 안다.

---

## ⓪ 언제 밟나 — 불렀을 때만

- `/design` 을 부르지 않았으면 이 절차는 없는 것이다. 그냥 부탁받은 일은 브랜치 → 작업 → PR 로 간다
- 그리는 게 나아 보이면 **한 줄로 제안하고 멈추지 않는다.** "시안 먼저 볼래요?" 한 번이면 된다.
  아니라거나 답이 없으면 그대로 진행한다. **두 번 묻지 않는다** — 잔소리는 하드룰 9 위반이다

## ① 무엇을 그릴지 정한다 — 먼저 문서를 연다

`start-task.md` ① 과 같다. 코드부터 보면 "지금 있는 것"에 생각이 갇히는 것도 같다.

1. `docs/04-기능-정의서-인덱스.md` 에서 기능을 찾는다
2. 그 행의 **Notion 링크를 연다** (`notion-fetch`)
3. 하드룰 칸에 `H*` 가 있으면 **CLAUDE.md 의 해당 하드룰을 같이 읽는다**
4. 기획서 절이 걸려 있으면 그것도 연다

기능이 인덱스에 없으면 새 기능이다. 시안 단계에서는 Notion 페이지를 아직 만들지 않는다 —
**무엇을 만들지가 시안으로 정해진 뒤에 적는 게 맞다.** 페이지는 `/task` 에서 만든다.

## ② 시안을 그린다 — 조건 셋

**이 셋이 시안을 그림에서 명세로 바꾼다.** 지키면 "이 여백 얼마예요"를 구현 중에 되물을 일이 없다.

1. 색 · 간격 · 라운드 · 폰트는 **`mobile/src/shared/config/theme.ts` 의 토큰에서만** 가져온다.
   시안에 hex 를 새로 짜내지 않는다 — 화면에 리터럴을 못 쓰게 한 규칙과 같은 규칙이다
2. 모양은 **`mobile/src/shared/ui/` 에 이미 있는 것만** 쓴다
   (`Card` `Button` `Input` `AmountInput` `Field` `Row` `Chip` `Notice` `ProgressBar` …)
3. **둘 중 하나가 모자라면 그리지 말고 열린 결정 Q 로 올린다.**
   새 토큰 · 새 공용 컴포넌트는 사용자 허락이 필요한 항목이라 (CLAUDE.md 「디자인 시스템 규칙」),
   구현 중에 슬쩍 생기면 안 된다. 시안 단계에서 걸러지는 게 제자리다

## ③ 반드시 같이 그리는 것

**예쁜 정상 화면 한 장만 올리면 사용자가 할 수 있는 건 승인뿐이고, 그건 관문이 아니다.**
에이전트가 뽑은 태스크 목록이 "그럴듯해 보이는 것"으로 실패하듯, 시안도 같은 방식으로 실패한다.

| 무엇을 | 왜 |
|---|---|
| **갈림길은 A/B 를 나란히** | 하나만 그리면 고르는 게 아니라 받아들이는 게 된다 |
| **빈 상태 · 실패 · 경계 화면** | 여기가 정해지지 않은 채 구현에 들어가면 설계 질문이 구현 도중에 터진다 (PR #57) |
| **시스템 글자 크게 켠 화면** | `allowFontScaling={false}` 를 금지했으므로 360dp 에서 잘리는지 그림에서 먼저 본다 |
| **밝게 / 어둡게** | 다크에서 깨지는 것은 토글해봐야 보인다 |

## ④ 아티팩트 한 장으로 낸다 — 고정 목차

칸을 고정한다. 매번 다른 모양으로 내면 사용자가 무엇을 봐야 하는지 매번 다시 찾아야 한다.

1. **한 줄 정의** — 누가, 언제, 무엇을 하려고
2. **화면** — 폰 폭(360dp) 프레임. 왼쪽에 그림, 오른쪽에 그 화면의 시나리오
3. **정상 흐름** — 「한 화면 = 한 질문」 위반이 있으면 여기서 드러난다
4. **빈 상태 · 실패 · 경계** — ③ 의 표대로
5. **데이터가 어떻게 변하나** — 어느 테이블에 무엇이 생기고 · 바뀌고 · **안 지워지나**
6. **하드룰 대조** — H1~H9 중 걸리는 것과, 어긋나지 않는 근거
7. **열린 결정 Q1…Qn** — 각각 「선택지 / 각각의 대가 / 내 추천」
8. **이번에 안 하는 것**

## ⑤ 승인을 받는다

**열린 결정이 하나라도 남아 있으면 끝이 아니다.** 여기서 "일단 이렇게 가정하고 진행하겠습니다"로
넘어가는 것이 이 절차를 만든 이유를 지우는 것이다. Q 가 닫힐 때까지 코드를 시작하지 않는다.

닫힌 Q 의 답은 **아티팩트에 반영해서 확정본을 만든다.** 대화에만 남기면 다음 세션이 못 읽는다.

## ⑥ `/task` 로 넘어간다 — ③ 은 건너뛴다

승인된 시나리오가 곧 태스크 목록이므로 `start-task.md` ③ 에서 다시 멈추지 않는다.
**이미 승인받았다.** ④ 이슈 → ⑤ 브랜치 → ⑥ 작업 순으로 간다.

이슈 본문에는 **아티팩트 링크를 남긴다.** 시안이 없으면 이슈만 읽고는 무엇을 만들지 알 수 없다.

## ⑦ 시안은 3층을 대신하지 못한다

커서 밀림 · 키보드 가림은 그림에 안 나온다 (시행착오 1-1 · 1-5).
**입력을 가공하는 화면은 시안이 아무리 정확해도 에뮬레이터에서 눌러봐야 한다.**
