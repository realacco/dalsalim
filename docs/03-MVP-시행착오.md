# 달살림 MVP 시행착오

> 2026-08-31 · 에뮬레이터에서 로그인부터 제출·요약·추이까지 직접 밟아보며 나온 기록
> 같이 볼 것: [01-MVP-기획서.md](01-MVP-기획서.md) · [02-MVP-출시-체크리스트.md](02-MVP-출시-체크리스트.md)

**이 문서를 남기는 이유.** 타입체크가 통과하고 API 스모크가 54개 다 초록이어도,
화면을 직접 눌러봐야만 드러나는 것이 있었다. 그중 하나는 **앱의 모든 금액을 틀리게 받는 버그**였다.
같은 함정을 다시 밟지 않으려고, 무엇이 어떻게 드러났는지를 적어둔다.

---

## 0. 무엇을 했나

새 계정으로 처음부터 끝까지 한 바퀴 돌렸다.

```
개발용 로그인 → 가족 만들기 → 고정비 등록 → 지난달 기록(API) →
이번 달 위저드 7스텝 → 사유 강제 확인 → 제출 → 월 요약 → 추이 → 가족(멤버 관리)
```

한글은 `adb shell input text`로 못 넣기 때문에 영문 이름(`dad` / `KimHouse` / `Rent`)으로 돌렸다.
프리필을 UI에서 확인하려면 지난달 기록이 있어야 해서, 그 부분만 API로 만들어두고 화면에서 확인했다.

## 1. 고친 것

### ★ 1-1. 금액 입력이 숫자를 틀리게 받았다 (치명)

**증상.** 빈 칸에 `800000`을 치면 **8,000,000**이 된다. 여섯 번 눌렀는데 일곱 자리가 나온다.
빠르게 쳐서 생긴 일인가 싶어 0.8초 간격으로 한 글자씩 다시 쳤는데 **똑같이 재현**됐다.

**원인.** `AmountInput`이 매 글자마다 3자리 콤마를 다시 붙이고 그 결과를 `value`로 되돌려줬다.
우리가 넣은 콤마 때문에 문자열이 사용자가 친 것보다 길어지고, 커서가 그만큼 뒤로 밀린다.
다음 숫자가 문자열 중간에 끼어들면서 전혀 다른 수가 된다.

**왜 심각한가.** 이 컴포넌트는 **앱의 모든 금액**이 지나가는 길목이다.
수입, 고정비 매 항목, 추가 지출, 고정비 기본 금액 — 전부. 가계부에서 숫자가 틀리면 앱 전체를 못 믿는다.

**고친 방법.** 타이핑하는 동안에는 콤마를 넣지 않고, 포커스가 빠질 때만 붙인다.
입력 중 문자열 길이가 절대 바뀌지 않으므로 커서가 밀릴 일이 없다.

> 안드로이드는 **뒤로가기로 키보드를 내려도 `onBlur`가 오지 않는다.** 그래서 다 적고 키보드만
> 내리면 콤마 없는 숫자가 계속 보였다. `keyboardDidHide`도 같이 들어서 편집 상태를 끝낸다.

**남은 트레이드오프.** 위저드는 금액 칸이 autoFocus라, 적는 동안에는 `3450000`처럼 콤마 없이 보인다.
바로 아래 "지난달보다 250,000원 많아요" 줄이 읽을 수 있는 형태를 계속 보여주고 있어서 그대로 뒀다.

### 1-2. 요약이 미제출자의 빈 줄을 0원으로 셌다

"전원 제출해야 요약이 열린다"는 잠금을 없앤 결과로 드러났다.
집계가 장부의 모든 기록을 훑고 `actualAmount ?? 0`으로 더하는데, **작성 중인 사람의 아직 안 적은 줄이
0원으로 섞여 들어간다.** 화면에는 "엄마 수입 0원"처럼 보인다. 안 쓴 게 아니라 아직 안 적은 것인데.

잠금이 있을 때는 이 경로가 열리지 않아 문제가 안 됐다. **잠금을 푸는 변경은 집계 범위를 같이 봐야 한다.**

→ 제출된 기록만 집계하고, 미제출자는 숫자에서 빼되 "아직 안 적었어요"로 표시한다.

### 1-3. 내보낸 멤버 때문에 장부가 영원히 안 닫혔다

멤버를 내보내면 정원이 2명에서 1명으로 준다. 그런데 **그 사람의 제출 기록은 장부에 그대로 남는다**
(과거를 지우지 않는 게 이 앱의 규칙이므로 의도된 것이다). 그래서 제출 수는 2, 정원은 1이 되어
`제출 수 === 정원`이 영원히 성립하지 않는다.

정원에서만 빼고 제출 수는 안 봤던 게 원인이다. **구성원이 바뀌면 양쪽 다 현재 구성원 기준으로 세야 한다.**
스모크에 "남은 사람만으로 장부가 완성된다"를 넣어두지 않았다면 못 잡았을 것이다.

### 1-4. 스모크 테스트가 두 번 돌지 않았다

두 번째 실행부터 18개가 `FORBIDDEN`으로 깨졌다. 앞선 실행이 남긴 제출 기록 때문이다.
매번 DB를 지우고 시드를 다시 넣어야 하는 건, 하루에도 수십 번 돌릴 스크립트에 붙은 큰 마찰이다.
→ 시작할 때 이번 달을 다시 열어 초기 상태로 되돌린다.

### 1-5. 고정비 시트의 [저장]이 키보드에 완전히 가려졌다

항목 이름을 누르면 키보드가 올라오면서 저장 버튼이 화면 밖으로 나간다. 스크롤해도 안 나온다.

`KeyboardAvoidingView`가 **시트만** 감싸고 있어서 줄어들 여지가 없었다.
키보드를 피해야 하는 건 시트가 아니라 **화면 전체**다. 바깥 컨테이너를 줄여야 아래 정렬된 시트가
키보드 위로 올라온다.

### 1-6. 가족 탭에 당겨서 새로고침이 없었다

가족이 방금 초대코드로 들어왔는지 확인하는 건 이 앱에서 **가장 자주 하는 동작**인데,
가족 탭만 새로고침이 없어서 앱을 껐다 켜는 수밖에 없었다. (다른 세 탭에는 다 있었다)

### ★ 1-7. 새 가족이 합류했는데 장부에 "완성" 배지가 그대로 있었다

아빠가 혼자 제출해서 장부가 `완성`이 된 뒤에 엄마가 초대코드로 들어왔다.
사람이 늘었으니 "전원 제출"에 필요한 정원도 늘었는데, **참여 경로에서 장부를 다시 계산하지 않아**
완성인 채로 남았다. 방금 들어온 사람은 한 줄도 안 적었는데 홈에 `완성` 배지가 떠 있다.

나갔던 사람이 되돌아오는 경로에는 재계산을 걸어뒀는데 **신규 참여 경로에는 빠뜨렸다.**
같은 일을 하는 두 갈래 중 하나만 고친 전형적인 실수다.

이건 화면을 안 봤으면 못 잡았다. 스모크는 "아빠 → 엄마" 순서로만 돌아서
**중간에 사람이 늘어나는 순서**를 밟지 않았기 때문이다. 그 케이스를 스모크에 추가했다.

### 1-8. 추이 차트의 양 끝 점이 반쯤 잘렸다

좌우 여백 없이 `x = 0`과 `x = width`에 점을 찍어서, 첫 달과 마지막 달의 점이 화면 밖으로 반쯤 나갔다.

### ★ 1-9. 첫 OTA 업데이트가 앱을 서버에서 끊었다

**증상.** OTA 를 처음 쏜 직후 APK 앱이 모든 화면에서 *"서버에 닿지 못했어요"* 를 띄웠다.
서버는 멀쩡했고(`/health` 200), 재설치하면 다시 정상이었다.

**원인.** `EXPO_PUBLIC_API_URL` 이 OTA 번들에 안 실렸다.

```
eas.json  build.preview.env.EXPO_PUBLIC_API_URL   ← eas build 만 읽는다
EAS 서버의 환경변수                                 ← eas update 는 이쪽을 읽는다
```

**둘은 다른 저장소다.** `eas.json` 에 적어둔 값은 빌드에만 들어가고, `eas update` 는
EAS 에 등록된 환경변수를 본다. 우리는 앞의 것만 채워뒀으니 업데이트 번들에는 주소가 비었고,
`resolveBaseUrl()` 이 폴백인 `http://localhost:4000` 으로 떨어졌다.

**왜 못 알아챘나.** 첫 발행 로그에 경고가 **찍혀 있었다.**

```
No environment variables with visibility "Plain text" and "Sensitive"
found for the "preview" environment on EAS.
```

"환경변수가 없다"를 정상으로 읽고 넘어갔다. 지금 보면 정확히 이 사고의 예고다.

**고친 방법.** EAS 에 프로젝트 환경변수를 등록했다.

```bash
eas env:set --name EXPO_PUBLIC_API_URL --value https://... \
  --visibility plaintext --environment preview --environment production
```

등록 뒤에는 발행 로그가 `... loaded from the "preview" environment on EAS: EXPO_PUBLIC_API_URL` 로 바뀐다.
**이 줄이 보이는지가 곧 검사다.**

**왜 위험한 모양인가.** 빌드는 초록이고 발행도 성공이고 앱도 켜진다 — 죽는 건 **서버 호출뿐**이다.
그리고 APK 안의 원본 번들에는 주소가 제대로 있어서, **재설치하면 낫는다.**
"재설치하면 되네"로 넘어가면 원인을 영영 못 찾고 매번 재설치하게 된다.

**남길 규칙.** **OTA 를 처음 붙인 날 곧바로 한 번 쏴본다.** 이 사고는 시험 발사에서 났다.
몇 주 뒤 진짜 급한 수정을 쏘다 났으면 원인 찾기가 훨씬 어려웠을 것이다.

> 곁가지: `app.json` 에 `platforms` 가 없으면 기본값이 `all` 이라 `eas update` 가 웹까지
> 내보내려다 `react-native-web` 이 없어서 실패한다. `["ios", "android"]` 로 명시했다.

### ★ 1-10. 같은 전제가 네 군데에 복사돼 있었고, 그게 전부 틀렸다

**증상.** 가족장이 참여 요청을 **거절**하면, 그 사람이 예전에 적은 기록이 DB 에서 같이 사라지고
**가족의 지난 달 합계가 바뀐다.** 스모크로 재현했을 때 8월 총계가 `300만 → 0` 이 됐다.

**원인.** `services/family.ts` **한 파일 안에서 두 주석이 서로를 반증하고 있었다.**

```
family.ts:66   재참여   → 있던 행을 PENDING 으로  "지난 기록이 이 멤버십에 매달려 있다"
family.ts:107  요청 취소 → membership.delete()   "승인 전이라 매달린 기록이 없다"
family.ts:147  요청 거절 → membership.delete()   같은 주석
```

`Membership` 은 `@@unique([familyId, userId])` 라 재참여가 행을 **새로 만들지 못하고 옛 행을 되살린다.**
그래서 **지난 제출본이 달린 `PENDING`** 이 존재한다. 위쪽 주석은 그걸 알고 있었는데 아래 둘이 몰랐다.

**왜 심각한가.** 하드룰 6 위반인데다, **거절은 가족장이 누르는 버튼**이다.
내보내기(F-FAM-09)로는 절대 못 하는 일 — 남의 과거 기록 지우기 — 을 거절 버튼으로는 할 수 있었다.
**삭제가 남을 향한 무기가 되는 모양**이라 위험도가 한 단계 위다.

**고친 방법.** 판단을 `discardJoinRequest()` **한 곳으로 모으고**, 딸린 게 없는 행만 지우고
있는 행은 `LEFT` 로 되돌린다. 지우는 쪽은 여전히 하드룰 6 근거 ①(집계에 한 줄도 안 들어간 것) 안이라
**새 예외를 만들지 않았다.**

**그런데 여기서 끝이 아니었다.** 같은 전제의 사본이 리뷰 라운드마다 하나씩 더 나왔다.

| | 무엇이 사라지고 있었나 | 어떻게 찾았나 |
|---|---|---|
| ① | 지난 달 **기록**(제출본) | 설계 문서를 쓰다가 |
| ② | 그 사람의 **고정비 항목** | 리뷰 — 「자식 행이 둘인데 하나만 세고 있다」 |
| ③ | 그 사람의 **정산일 설정** | 리뷰 — 「행이 **직접 든 값**도 있다」 |
| ④ | `CLAUDE.md` 하드룰 6 의 **예시 한 줄** | 리뷰 — 「코드는 고쳤는데 근거 문서가 옛말을 한다」 |

②와 ③ 은 **내가 판 구멍을 내가 다시 판 것**이다. ② 를 고치면서 「자식 행」만 떠올렸고,
행 자신이 들고 있는 값(`settlementDay`)은 생각하지 못했다. 처음부터 스키마를 열어
**「이 행에 매달린 것 + 이 행이 든 것」을 한 번에 세었으면** 한 번에 끝났을 일이다.

④ 가 제일 무섭다. `CLAUDE.md` 는 **매 요청마다 컨텍스트에 실리는 파일**이라,
그 한 줄이 남아 있으면 다음 사람(또는 다음 에이전트)이 같은 전제로 또 `delete` 를 쓴다.
세 번째 사본이 안 생기게 함수를 한 곳으로 모았는데, **근거 문서가 갈라져 있으면 소용이 없다.**

> 기능 정의서(Notion)도 같은 모순을 갖고 있었다 — F-FAM-03 은 맞게 적혀 있었고
> F-FAM-04 · F-FAM-05 는 「승인 전이니 매달린 기록이 없다」를 **「명시적 예외」로 승격**까지 해뒀다.
> **코드가 스펙을 잘못 구현한 게 아니라 스펙이 틀렸고 코드가 충실히 따른 것**이다.
> 기획서 3장만은 처음부터 맞았다 — 「나갔다가 다시 신청해 대기 중인 사람도 그 달에 냈으면 같다」.

**곁가지 — 테스트가 초록인데 그 경로를 안 거칠 수 있다.** ②·③ 의 케이스가 `reject` 응답을
안 보고 있었다. 거절이 실패하면 행이 `PENDING` 으로 남는데, 뒤의 재요청이 **아직 살아 있는 그 id** 를
그대로 집어 승인까지 통과한다 — **거절을 한 번도 안 거친 채 초록**이 된다.
서버를 깨뜨려 빨개지는 것은 확인했지만 **스모크 자신이 어긋나는 경우**는 안 봤던 것이다.

### ★ 1-11. 라이브러리를 **불러오기만 해도** 던져서 앱이 통째로 안 떴다

Android Expo Go 에서 앱이 시작되자마자 빈 화면으로 죽었다. 로그에는
`Route ./_layout.tsx is missing the required default export` 가 찍혔는데, 정작 그 파일에는
default export 가 멀쩡히 있었다. **모듈 평가가 실패하면 expo-router 는 "export 가 없다" 로 말한다** —
증상과 원인의 이름이 다르다.

원인은 `expo-notifications` 였다. 이 패키지는 `index` 에서 `DevicePushTokenAutoRegistration.fx` 를
다시 내보내고, 그 파일이 **불러오는 것만으로** 최상단에서 `addPushTokenListener` 를 부른다.
그 함수는 Expo Go + 안드로이드면 그 자리에서 `throw` 한다 (SDK 53 부터 원격 푸시가 Expo Go 에서 빠졌다).
그래서 그 모듈을 임포트한 `features/push` → `app/_layout` 이 통째로 평가에 실패했다.

> 🔴 **우리 쪽 `try/catch` 는 함수 호출을 감싼 것이라 이 예외의 밖이었다.**
> 토큰 발급(`getExpoPushTokenAsync`)은 감싸 뒀고 주석도 「Expo Go 에서는 토큰이 안 나온다」 까지만
> 가정하고 있었다. 실패가 **한 단계 앞(임포트)** 에서 났다.

고침은 `features/push` 입구에서 `isRunningInExpoGo()` 로 갈라 **그 모듈을 아예 안 읽는 것**이다.
개발 빌드로 갈아타는 쪽은 버렸다 — Expo Go 로 바로 도는 개발 루프를 잃는다.

**남길 것**
- 부수효과 파일(`*.fx`)을 가진 패키지는 **임포트 자체가 실행**이다. 실행 환경이 갈리는 기능이면
  `try/catch` 가 아니라 **임포트를 가른다.**
- 환경 갈림은 **모듈 로드 때 한 번만** 정한다. 훅을 조건부로 부르지 않기 위해서다.
- 3층이 밀리면 이런 것이 몇 주 동안 안 보인다. 이 버그는 `expo-notifications` 가 들어온 날
  (2026-09-15, #48) 부터 있었고, 그 뒤 확인은 APK 로만 했다.

## 3. 도구·환경에서 겪은 것

앱 문제는 아니지만 다음에 또 만날 것들이라 적어둔다. (환경 함정 전반은 `docs/개발-노트.md` — 로컬 전용)

- **`adb shell input text`는 한글을 못 넣는다.** 그래서 시나리오를 영문 이름으로 돌렸다.
  덕분에 한글 입력 경로(초대코드 화면의 표시 이름 등)는 손으로 확인해야 한다.
- **`adb shell input text "a b"`는 공백에서 잘린다.** 특이사항에 "Hot summer, aircon a lot"을 넣었는데
  `Hot`만 저장됐다. 앱이 자른 게 아니다.
- **에뮬레이터를 5시간 넘게 띄워두면 망가진다.** 부하가 22까지 오르고 `input` 서비스가 사라져
  `am start`가 "Too early to start activity"로 계속 실패했다. `boot_completed`는 1인데도 그랬다.
  → 콜드 재시작이 답이다. 그리고 **`adb emu kill`이 안 먹을 때가 있다** — qemu 프로세스를 직접 죽여야 했다.
- **Metro 포트 8081이 잡혀 있으면 `expo start`가 비대화형에서 멈춘다.** ("Use port 8082 instead?"를
  물어보고 답을 못 받아 dev server를 건너뛴다) 새로 띄우기 전에 포트를 비워야 한다.
- **`scripts/dev.js`가 에뮬레이터 부팅 직후 Expo Go를 열려다 죽는다.** `boot_completed`만 보고
  바로 `am start`를 부르는데, 그 시점엔 아직 액티비티를 띄울 수 없다. 재시도가 필요하다.
- **에뮬레이터 준비를 기다리는 조건을 두 번 틀렸다.**
  처음엔 `service check input | grep found`가 **"not found"에도 매칭**돼서 아직 안 뜬 에뮬레이터를
  준비됐다고 봤다. 고친다고 `grep "Service input: \["`로 바꿨는데, **이 빌드는 대괄호 형식을 안 쓴다** —
  실제 출력은 그냥 `Service input: found`다. 그래서 이번엔 영원히 안 끝나는 루프가 됐다.
  → **기다리는 조건을 쓰기 전에 그 명령의 실제 출력을 먼저 찍어보고 맞춘다.**
     한쪽으로 틀리면 없는 준비를 있다고 하고, 반대로 틀리면 끝나지 않는다.

## 4. 남길 규칙

이번에 데인 것 중 다시 데지 않으려면 규칙으로 남겨야 하는 것들. (`CLAUDE.md`에 반영)

1. **입력 중에는 표시 형식을 바꾸지 않는다.** 컨트롤드 입력에서 우리가 문자열 길이를 바꾸면
   커서가 밀리고, 다음 글자가 엉뚱한 자리에 들어간다. 포맷은 포커스가 빠질 때 붙인다.
2. **잠금을 푸는 변경은 집계 범위를 같이 본다.** 막혀 있던 경로가 열리면 그동안 안 드러났던
   계산이 화면에 나온다.
3. **구성원이 바뀌는 기능은 "정원"과 "실적"을 둘 다 현재 구성원 기준으로 센다.**
   그리고 **구성원이 바뀌는 경로를 전부 찾아서** 같은 재계산을 건다 — 참여·재참여·나가기·내보내기.
   하나만 빠져도 그 경로로 들어온 사람에게만 틀린 화면이 보인다.
4. **테스트 스크립트는 몇 번이고 다시 돌 수 있어야 한다.** 한 번만 도는 스크립트는 곧 안 돌리게 된다.
5. **같은 값이 두 곳에 있으면 두 곳을 다 고친다.** 빌드용 설정과 배포용 설정처럼
   저장소가 갈린 값이 특히 그렇다 — 한쪽만 고치면 **모든 검사가 초록인 채로** 실행 중에만 깨진다.
   그리고 **새 배포 경로를 붙인 날 곧바로 한 번 써본다.** 1-9 는 시험 발사에서 났고,
   몇 주 뒤 급한 수정을 쏘다 났으면 원인 찾기가 훨씬 어려웠다.
6. **타입체크와 API 스모크가 통과해도 화면은 따로 봐야 한다.** 1-1은 두 관문을 모두 통과한 채
   숨어 있었다. 서버가 받은 값은 늘 유효한 정수였기 때문이다.
7. **같은 판단이 두 곳에 있으면 한쪽만 고쳐진다 — 그리고 문서도 사본이다.**
   1-10 에서 같은 전제가 코드 둘 · 기능 정의서 둘 · `CLAUDE.md` 하나에 퍼져 있었다.
   함수를 한 곳으로 모으는 것만으로는 안 끝난다. **판단을 옮겼으면 그 판단의 근거 문서도 같이 옮긴다** —
   특히 `CLAUDE.md` 는 매 요청마다 실려서, 거기 남은 옛말이 다음 사람을 같은 함정으로 데려간다.
8. **「행을 지운다」의 파급은 자식 행만이 아니다.** 스키마를 열어 **이 행에 매달린 것**(Cascade 가
   쓸어갈 자식)과 **이 행이 직접 든 것**(스칼라 컬럼)을 **한 번에** 센다.
   1-10 에서 자식 하나 → 자식 둘 → 행이 든 값까지, 세 번에 걸쳐 하나씩 찾았다. 한 번에 끝날 일이었다.
