# 테스트 규칙

> **언제 읽나:** 테스트를 새로 짜거나 고칠 때 · 하드룰을 건드리는 변경을 할 때.

검증은 **3층**이고, 층마다 잡는 것이 다르다. 위층이 아래층을 대신하지 못한다.

| 층 | 도구 | 무엇을 | 언제 | 얼마나 |
|---|---|---|---|---|
| **1. 순수 함수** | **vitest** | 도메인 규칙 · 표시 형식 · **서버/앱 사본 일치** | 커밋마다 (pre-commit) | ~0.5초 |
| **2. API 흐름** | `server/scripts/smoke.mjs` | 사유 강제 · 승인 구조 · 장부 상태 전이 · 집계 범위 | 서버 로직을 바꾸면 · CI | ~10초 |
| **3. 화면** | **사람** (에뮬레이터) | 입력 가공 · 커서 · 키보드 | 그 화면을 건드릴 때 | — |

```
npm test          # 1층 전부 (루트에서)
npm run test:watch
cd server && node scripts/smoke.mjs   # 2층
```

- **3층은 자동화하지 않는다.** RN 화면 테스트는 유지비가 크고, 커서 밀림 같은 건
  결국 사람이 눌러봐야 안다 — 시행착오 1-1 이 그 증거다.
- ⚠️ **1층과 2층이 통과해도 화면은 따로 봐야 한다.** 서버가 받는 값이 늘 유효한 정수여도
  사용자가 친 것과 다를 수 있다. 금액·날짜처럼 **입력을 가공하는 화면은 반드시 에뮬레이터에서 눌러본다.**

### 어디에 무엇을 두나

| | 위치 | 무엇을 |
|---|---|---|
| 1층 · 서버 | `server/src/**/*.test.ts` | 소스 옆에 나란히 둔다 |
| 1층 · 앱 | `mobile/src/**/*.test.ts` | 같음. **`entities/*/model` 이 순수해야 하는 이유가 이것이다** |
| 1층 · 계약 | `tests/contract/*.test.ts` | ★ 서버와 앱에 **각각** 있는 같은 함수가 진짜 같은지 |
| 1층 · 도구 | `tests/tools/*.test.mjs` | 커밋 훅이 쓰는 스크립트 (비밀 스캔 규칙) |
| 2층 | `server/scripts/smoke.mjs` | 기획서 10장의 성공 기준 시나리오를 그대로 따라간다 |

### 지킬 것

- **하드룰을 건드리는 변경은 테스트에 케이스를 추가해야 완료다.** 예외 없다.
  특히: 사유 강제 · 사유 자동 삭제 · 프리필 우선순위 · 장부 상태 전이 · 요약 집계 범위
- 🔴 **서버와 앱에 같은 함수를 두면 `tests/contract` 에 일치 케이스를 같이 넣는다.**
  지금 네 쌍이다 — `needsReason` · `shiftYearMonth` · `currentYearMonth` · `CATEGORIES`.
  한쪽만 고치면 아무 경고 없이 갈라지고, 결과는 "저장은 되는데 [다음] 이 안 눌린다"처럼
  원인을 찾기 어려운 형태로 나타난다. 이 파일이 그걸 막는 **유일한** 자동 장치다.
- **버그 수정은 실패하는 케이스부터.** 재현 케이스를 먼저 넣어 빨간 것을 확인하고 고친다.
- **넣은 테스트는 일부러 깨뜨려 확인한다.** 코드를 비틀었을 때 빨개지지 않는 테스트는
  없는 것과 같다. (린트 규칙도 마찬가지다 — M-1 에서 실제로 데였다)
- **테스트는 몇 번이고 다시 돌 수 있어야 한다.** 한 번만 도는 스크립트는 곧 아무도 안 돌린다.
- 케이스 이름은 **한국어로 행동을 쓴다.** 하드룰을 지키는 케이스에는 `★` 를 붙인다.
- 🔴 **기능 정의서의 시나리오를 따라가는 케이스에는 기능 ID 를 앞에 적는다.**
  (`★ F-ENT-04 금액이 달라지면 사유 없이는 막힌다`)
  주석과 인덱스는 그 기능이 **어디 있는지**만 말한다. 테스트는 **무엇을 하기로 했는지를 실행한다** —
  Notion 문서와 코드를 실제로 묶는 건 이것 하나뿐이다. 문서가 낡으면 조용하지만 테스트는 빨개진다.
  **판단 기준은 "중요한가"가 아니라 "붙일 ID 가 실재하는가"다.** 다음 넷에는 붙이지 않는다 —
  ① 도구 테스트(`tests/tools`, 인덱스 검사) ② 계약 테스트(축이 기능이 아니라 **두 사본의 일치**다)
  ③ 여러 기능이 함께 쓰는 유틸(금액 표기 · `shiftYearMonth`) ④ 원본이 기능 정의서가 아니라
  CLAUDE.md 인 것(말투 · 응답 형태 · `fail()`).
  **전부 붙이면 안 붙인 것과 같아진다** — `grep` 이 스무 건을 뱉는 ID 는 역인덱스 구실을 못 한다.
- **문구가 아니라 `code` 로 검증한다.** 에러 메시지는 말투가 바뀔 수 있지만 `code` 는 계약이다.
- 서버 로직을 바꾸면 **앱을 켜기 전에 스모크부터** 돌린다. 에뮬레이터로 디버깅하는 것보다 훨씬 빠르다.
