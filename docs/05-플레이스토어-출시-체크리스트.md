## 1. 🔴 코드가 있어야 통과하는 것

### 1-1. 계정 삭제 — `F-SES-08` 탈퇴

Play 는 **앱 안에서 계정을 삭제하는 길**과 **앱을 지운 사람도 쓸 수 있는 웹 링크** 둘 다를 요구하고,
삭제하면 **그 계정에 딸린 데이터도 지워야** 한다. 웹 링크는 데이터 보안 양식에 적는다.

- [ ] **정책 결정** (5-1) — 하드룰 6(과거를 지우지 않는다)과 정면으로 부딪친다. 내 `EntryLine` 은 가족 장부의 합계에 들어가 있어서, 지우면 다른 사람의 지난 달 숫자가 바뀐다
- [ ] `DELETE /me` — 사용자 행 · 멤버십 · 푸시 토큰. 기록은 정책대로
- [ ] 앱 — 내 정보 화면(`F-SES-06`, PR #52)에 「탈퇴」. 정의서가 그 자리를 이미 비워 뒀다
- [ ] **웹 삭제 요청 페이지** — 서버에 정적 라우트 하나면 된다 (`GET /account/delete` · Railway 가 이미 https 다). 카카오 로그인 → 확인 → `DELETE /me` 순서
- [ ] `F-SES-08` 정의서 · 인덱스 행 · 기획서 4장

**전제**: 혼자 남은 가족장은 가족을 먼저 없애야 한다 — `F-FAM-11` (PR #50) 이 그걸 만든다. 그게 없으면 탈퇴한 가족장 뒤에 승인할 사람 없는 가족이 남는다.

### 1-2. 개인정보처리방침 — 공개 URL

스토어 등록정보와 데이터 보안 양식 둘 다에 URL 을 적어야 한다. **지금 문서 자체가 없다.**

- [ ] 문서를 쓴다. 수집 항목은 아래 3-5 의 표가 곧 목록이다
- [ ] **어디에 올리나** — 서버 정적 라우트(`GET /privacy`) 가 가장 싸다. 1-1 의 삭제 페이지와 같은 자리
- [ ] 보관 기간 · 파기 절차 · 제3자 제공 없음 · 서버 위치(Railway 리전) · 연락처
- [ ] ⚠️ `User.profileImageUrl` — **저장하지만 어디에도 안 그린다** (`<Image>` 가 한 곳도 없다). 방침에 "수집한다"고 적느니 **안 받는 게 낫다.** 5-1 참조

> 금융 라이선스(마이데이터 등)는 필요 없다. 계좌·카드를 연동하지 않고 사용자가 직접 적는다 (기획서 4장 「아예 안 하는 것」).

### 1-3. 심사용 로그인 — 카카오뿐이라 리뷰어가 못 들어온다

Play 는 로그인이 필요한 앱에 **언제든 쓸 수 있고 재사용 가능하며 지역과 무관하게 유효한** 계정 정보를 요구한다.
지금 운영 서버의 로그인은 **카카오 하나**고, `/auth/dev` 는 운영에서 **라우트 자체가 없다** (보안 규칙 — 이건 그대로 둔다).
카카오 계정은 한국 전화번호가 있어야 만들어져서 해외 리뷰어에게 "카카오로 로그인하세요"는 답이 안 된다.

- [ ] **방식 결정** (5-2) — 후보 셋
  - 리뷰어용 카카오 계정을 우리가 만들고 **비밀번호를 콘솔에 적는다** — 가장 단순. 2단계 인증을 끄고 유지해야 한다
  - 운영에도 **심사 전용 로그인**을 둔다 — `/auth/review` 같은 라우트를 환경변수 비밀 코드로만 열고, 심사가 끝나면 끈다. `/auth/dev` 와 다른 점: 아무나 이름을 대는 게 아니라 **긴 비밀값**을 대야 한다
  - 둘 다 안 하고 「로그인 없이 볼 수 있는 화면은 없다」고 적는다 — **거절될 가능성이 높다**
- [ ] 콘솔 「앱 액세스」에 절차를 적는다 — 로그인 뒤 **가족 참여까지** 이어져야 한다. 리뷰어가 빈 온보딩 화면만 보고 끝나면 기능을 못 본다 → 승인된 가족이 있는 계정이어야 한다

### 1-4. 🔨 가족 없애기 — PR #50

- [ ] 머지. 1-1 의 전제

| 선택 | 하드룰 6 | Play 정책 | 결과 |
|---|---|---|---|
| **A. 계정만 지우고 기록은 남긴다** — `User` 행을 지우거나 익명화하고, `Membership` 은 `LEFT`, `EntryLine` 은 그대로 | ✅ 지킨다 | ⚠️ "계정에 딸린 데이터를 지운다"와 부딪칠 수 있다. **가족 장부의 일부라 지우면 남의 숫자가 바뀐다**는 사유를 방침에 명시하면 통상 허용되는 범주다 — 다만 확정은 심사가 한다 | 가족 합계가 안 흔들린다 |
| **B. 기록까지 지운다** | ❌ 깨진다 | ✅ 깔끔 | 탈퇴자가 있던 달의 가족 합계가 **바뀐다.** `F-BOOK-02` 가 막으려던 바로 그 일 |
| **C. 혼자인 가족은 없애고(F-FAM-11), 남이 있는 가족의 기록은 A** | ✅ | A 와 같음 | **정의서 `F-FAM-11` 이 이미 이 방향을 전제한다** |

권장은 **C**. 이유는 `F-FAM-11` 정의서에 이미 적혀 있다 — *"탈퇴 전에 혼자인 가족을 먼저 없애게 한다. 이 기능이 그 전제다."*

같이 정할 것: **`profileImageUrl` 을 아예 안 받는다** (스키마 컬럼 삭제 → 마이그레이션 · 카카오 동의항목 끄기). 수집 항목이 하나 줄고, 방침이 한 줄 짧아진다.

### 5-2. 리뷰어는 어떻게 들어오나

1-3 의 셋 중 하나. **첫 번째(리뷰어용 카카오 계정)** 가 코드를 안 건드리고 보안 규칙도 안 건드린다.
두 번째를 고르면 `/auth/dev` 를 여는 게 아니라 **별도 라우트**를 새로 판다 — 보안 규칙 「`/auth/dev` 는 운영에서 등록되지 않는다」는 그대로다.

### 5-3. 개인 계정이냐 조직 계정이냐

개인이면 **12명 × 14일**이 통째로 일정에 들어간다. 조직이면 면제지만 사업자등록이 든다.
가족 앱이라 12명을 모으는 게 진짜 허들이다 — **테스터 모집을 3-4 보다 먼저** 시작한다.
