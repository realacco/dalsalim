# 작업 흐름 — 기능 ID 로 열고 이슈로 닫는다

> **언제 읽나:** 새 기능을 시작할 때 · 이슈/브랜치/PR 이름을 정할 때 · 명령이 문서와 어긋날 때.
`/task` 스킬과 `.claude/hooks/` 가 이 절차의 기계 판정본이다.

**코드를 고치기 전에 어느 기능인지부터 정한다.** 모르면 사용자에게 묻는다.

```
① 기능 정의서(Notion) + 기획서의 해당 절을 읽는다
② 주석·인덱스로 지금 코드가 어디까지 와 있는지 본다
③ 태스크를 산정해 사용자에게 확인받는다      ← 여기서 한 번 멈춘다
④ GitHub 이슈를 만든다        [F-FAM-05] 참여 요청 승인·거절
⑤ 브랜치를 만든다             feat/F-FAM-05-approve-join
⑥ 작업 · 커밋                 Feature: F-FAM-05  /  Closes #12
⑦ PR → CI → 머지 → 이슈 닫힘. 닫힌 이슈는 다시 보지 않는다
```

③ 을 건너뛰지 않는다. 에이전트가 뽑은 태스크 목록은 **초안이지 계획이 아니다** —
그럴듯해 보이는 것이 이 단계의 실패 방식이라, 이슈로 굳히기 전에 사람이 한 번 본다.

**대부분의 일은 이 사이클을 밟지 않는다.** 기본은 **브랜치 → 작업 → PR** 이고 이슈는 없다.
PR 이 기록이다. 즉흥으로 부탁한 작은 수정에까지 문서와 이슈를 요구하면 규칙이 통째로 우회당한다.

가르는 축은 **"중요한가" 가 아니라 "되돌릴 수 있나"** 다. 되돌리기 어려운 네 가지 —
`/task` 호출 · 커밋이 `feat` 가 되는 변경(사용자에게 보이는 새 동작) · 하드룰이 걸린 파일 ·
`schema.prisma` — 일 때만 위 사이클을 밟는다.
넷 다 판단이 아니라 관찰이고, **걸리면 묻지 말고 이슈를 만든다.**
"애매한가?" 를 판단하기 시작하면 그 판단이 매번 흔들린다. 자세한 것은
`.claude/process/start-task.md` ⓪ 에 있다.

### 이름 규칙

| | 형식 | 예 |
|---|---|---|
| 브랜치 | `<type>/<F-ID>-<kebab>` | `feat/F-FAM-05-approve-join` |
| 이슈 제목 | `[F-ID] 기능 이름` | `[F-FAM-05] 참여 요청 승인·거절` |
| PR 제목 | 이슈와 같게 | |
| 커밋 트레일러 | `Feature: F-ID` (여럿이면 쉼표) | `Feature: F-FAM-05, F-BOOK-04` |
| 테스트 이름 | `★ F-ID 행동` | `★ F-ENT-04 금액이 달라지면 사유 없이는 막힌다` |
| 이슈 라벨 | 도메인 5개 | `session` `family` `fixed-expense` `book` `entry` |

- **`feat/` 만 기능 ID 가 필수다.** `chore/` `docs/` `ci/` `deps/` 는 없어도 된다.
  오타 수정·의존성 갱신에까지 이슈를 요구하면 **규칙이 통째로 우회당한다** — 구멍을 즉흥으로
  뚫게 두지 말고 모양을 미리 정해 둔 것이다. `fix/` 는 권장이되 강제하지 않는다.
- **1 기능 ID = 1 브랜치 = 1 PR.** 안의 태스크는 커밋으로 나눈다.
  이슈마다 브랜치를 쪼개면 스쿼시 머지에서 중복 커밋 충돌이 매번 난다 (PR #2·#3 에서 실제로 데였다).
- 이슈는 **기능당 에픽 하나 + 본문 체크박스**로 둔다. 열두 개를 미리 만들면 셋을 하는 사이
  나머지 아홉이 낡는데, 이슈는 낡은 채로도 권위 있어 보인다. 체크박스는 부담 없이 고쳐 쓴다.

### 명령이 문서와 다를 때 — 네 갈래

| 무엇과 어긋나나 | 어떻게 한다 |
|---|---|
| **기획서 · 하드룰** | **멈추고 묻는다.** 근거로 기획서의 절을 댄다. 제품 자체가 달라지는 변경이다 |
| **기능 정의서** | 양쪽 근거를 대고 묻는다. **코드가 맞을 수도 있다.** 정해지면 진 쪽을 고친다 |
| **문서만 낡음** (이름 · 메시지 코드 · 인덱스 경로) | 묻지 않는다. **고치고 진행하고 보고만 한다** |
| 어긋나지 않음 | 그냥 진행한다 |

셋째 줄만 자동으로 흘러간다. **판단이 필요한 위의 둘은 자동화하지 않는다** —
사실 확인은 물어볼 게 없지만, 제품 결정을 대신 내리는 것은 다른 종류의 일이다.
