# 달살림 MVP 출시 체크리스트

> v2.0 · 2026-08-31 · 현재 코드 상태 기준
> 이 문서에서 말하는 **"출시"는 스토어 등록이 아니라 "우리 가족이 실제로 매달 쓰기 시작하는 것"**이다.
> 기획: `01-MVP-기획서.md`

## 0. MVP 출시의 정의 — 스토어는 지금 하지 않는다

| | **A. 가족 내부 배포 ← 이번 목표** | **B. 스토어 공개 (나중)** |
|---|---|---|
| 배포 방법 | APK 직접 전달 / Play 내부 테스트 | Play Store · App Store 정식 등록 |
| 개인정보처리방침 | 있으면 좋음 | **필수** (공개 URL) |
| 계정 삭제 기능 | 없어도 됨 | **필수** (앱 내 + 웹 링크) |
| 스토어 등록정보·스크린샷 | 불필요 | 필수 |
| Play 비공개 테스트 20명 × 14일 | 불필요 | 개인 계정이면 필수 |
| **실작업** | **약 5~6일** | **+ 3~4주 (대기 포함)** |

### 왜 A만 하는가

B 항목의 대부분은 **제품을 좋게 만드는 일이 아니라 심사를 통과하는 일**이다.
그리고 이 앱은 **두 번째 달부터 진가가 드러나는 구조**다 (기획서 10장 성공 기준 5번).
석 달 써보기 전에는 스크린샷에 뭘 담아야 할지도 모른다.

> **세 달 쓰고 → 반드시 나올 불만을 고치고 → 그 다음에 스토어.**
> 그게 스크린샷을 두 번 찍지 않는 길이다.

## 1. 🔴 제품에 뚫려 있는 구멍 — 이게 제일 먼저다

기능이 없어서가 아니라 **설계상 막다른 길**이라 반드시 메워야 한다.
셋 다 기획서 4장의 v0.1 항목 7·8·9다.

### 1-1. ★ 안 쓰는 멤버 한 명이 장부를 영원히 막는다

현재 코드는 `GET .../summary`가 전원 제출 전이면 **409 `BOOK_NOT_COMPLETE`**를 낸다. 그래서:

- 가족 중 한 명이 앱을 안 쓰기 시작하면 → **그 달부터 아무도 요약을 못 본다**
- 잘못 초대한 사람이 있어도 → **뺄 방법이 없다**
- 출장·입원·그냥 바쁜 달이 있어도 → **그 달은 영원히 미완성**

**세 달만 써도 반드시 부딪힌다.** 기획서 3장에서 이 잠금을 없애기로 했다.

- [ ] `summary`에서 `BOOK_NOT_COMPLETE` 409 제거 → 항상 200
- [ ] 응답에 `submittedCount` / `memberCount` / `pendingMembers` 추가
- [ ] 앱: 요약 상단에 `엄마가 아직 안 적었어요 — 아래 숫자는 2명 기준입니다` 배너
- [ ] `MonthlyBook.status`는 남긴다 — **잠금장치가 아니라 표시**로만 쓴다

> 서버는 `refreshBookStatus()` 한 곳에 완성 판정이 모여 있어 손댈 곳이 적다.

### 1-2. 가족에서 나가고 내보낼 수 있어야 한다

- [ ] **가족 나가기** (본인)
- [ ] **멤버 내보내기** (OWNER)
- [ ] **가족장 이양** — OWNER가 나가면 가족이 주인 없이 남는다
- [ ] 나간 멤버의 **과거 기록은 지우지 않는다** (지우면 지난달 합계가 바뀐다).
      `Membership`을 비활성으로 두고 기록은 남기는 쪽

### 1-3. 추이 화면이 없다

엑셀 대비 이 앱이 이기는 지점인데 아직 없다. (기획서 7.5)

- [ ] `GET /families/:familyId/trend?months=12`
- [ ] 탭 4개 구성으로 변경 (이번 달 · 고정비 · **추이** · 가족)
- [ ] 라인 3개(수입 / 고정비 / 남은 돈) + 월별 표
- [ ] 데이터 1개월 이하일 때 안내 문구

## 2. 보안

### 2-1. `DEV_LOGIN` 차단 (치명적) — ✅ 코드로 막음

```
POST /auth/dev { "name": "아빠" }  →  토큰 발급
```

**이름만 알면 아무나 그 사람이 된다.**

- [x] 기본값을 **꺼짐**으로 바꿨다 — `.env`에 `DEV_LOGIN=true`를 직접 적어야만 켜진다
- [x] `NODE_ENV=production`이면 켤 수도 없고, `/auth/dev` **라우트를 아예 등록하지 않는다**
      (환경변수 실수 하나로 뚫리는 구조를 남기지 않는다. 핸들러 안에도 검사가 한 겹 더 있다)
- [x] 앱의 개발용 로그인 UI는 `/auth/config`를 따라 자동으로 사라진다
- [ ] 그래도 배포 뒤 `GET /health`의 `devLogin`이 `false`인지 눈으로 확인한다

### 2-2. `JWT_SECRET` 실제 값으로 — ✅ 코드로 막음

기본값 `dalsalim-dev-secret-change-me`가 알려지면 **아무 사용자로도 위조 가능**하다.

- [x] 운영에서 기본값이면 **서버가 아예 뜨지 않는다** (조용히 도는 것보다 안 뜨는 게 낫다)
- [ ] 랜덤 32바이트 이상으로 교체 (`openssl rand -base64 32`)
- [ ] 저장소에 커밋하지 않는다 (`.env`는 이미 `.gitignore`에 있다)

### 2-3. HTTPS

- [ ] 토큰이 평문으로 다니면 안 된다
- [ ] 카카오 Redirect URI도 운영에서는 https를 요구한다

### 2-4. 레이트리밋 — ✅ 적용

- [x] `@fastify/rate-limit` 추가. 전역 분당 300회,
      키는 로그인했으면 사용자 id, 아니면 IP (한 집에서 공유기를 같이 쓰므로 IP 로만 묶으면 서로 갉아먹는다)
- [x] `POST /families/join` 분당 10회 — 초대코드 무작위 대입 차단
- [x] `POST /auth/kakao/*` 분당 10회

### 2-5. 초대코드만으로는 못 들어온다 — ✅ 승인 구조

초대코드는 카톡으로 오가는 문자열이라 언제든 새어나갈 수 있다. 그것 하나로 남의 가계부가 열리면 안 된다.

- [x] 코드를 맞혀도 `PENDING`(승인 대기)으로 들어간다. 가족장이 승인해야 `ACTIVE`가 된다
- [x] `PENDING`은 가계부를 한 줄도 못 보고, 장부 정원("전원 제출")에도 안 들어간다
- [x] 내보낸 사람이 코드로 되돌아오는 것도 막힌다 — 재참여도 다시 승인을 받는다
- [x] 가족장은 [가족] 탭에서 승인/거절한다. 요청이 있으면 [이번 달] 홈에도 뜬다
      (푸시 알림이 없어서, 안 알려주면 요청이 들어온 줄 모른다)
- [ ] 푸시 알림이 붙으면 홈 안내는 보조 수단으로 물러난다 (9단계)

## 3. 서버를 세상에 올리기

지금은 `localhost:4000` + SQLite 파일이고 `adb reverse`로만 닿는다. **앱은 서버 없이 아무것도 못 한다.**

- [ ] 호스팅 선택 — Railway / Render / Fly.io 아무거나. Fastify + Prisma는 어디든 뜬다
      (한국 사용자만 쓰면 리전을 도쿄·서울 근처로)
- [ ] **SQLite → PostgreSQL** — `schema.prisma`의 `provider`와 `DATABASE_URL`만 교체.
      **애플리케이션 코드 변경 0.** 지금 스키마에 SQLite 전용 문법은 없다
- [ ] **마이그레이션 체계로 전환** — 지금은 `prisma db push`(스키마 덮어쓰기)다.
      운영은 `prisma migrate dev`로 파일을 만들어 커밋하고 `prisma migrate deploy`로 배포한다.
      **데이터가 쌓인 뒤 `db push`를 쓰면 컬럼이 날아갈 수 있다**
- [ ] `PUBLIC_BASE_URL`을 실제 도메인으로 (카카오 redirect_uri가 이 값으로 만들어진다)
- [ ] `HOST=0.0.0.0` 확인 (이미 기본값)
- [ ] **자동 백업** — 가계부는 날아가면 복구할 방법이 없다. 매일 덤프 + 보관 주기
- [ ] 앱의 `EXPO_PUBLIC_API_URL`을 운영 주소로 (**빌드 시점에 박힌다**)

## 4. 카카오 로그인 실제로 켜기

지금은 키가 없어 개발용 로그인만 동작한다. 붙이는 절차는 `README.md`에 있다.

- [ ] 카카오 개발자 콘솔에서 앱 생성
- [ ] **REST API 키** → 서버 `.env`의 `KAKAO_REST_API_KEY`
- [ ] 카카오 로그인 활성화 + **Redirect URI** 등록: `https://<운영도메인>/auth/kakao/callback`
- [ ] 동의항목: **닉네임(profile_nickname)**만. 프로필 이미지는 선택
- [ ] 플랫폼에 Android 패키지명(`com.dalsalim.app`) / iOS 번들ID 등록
- [ ] 실기기에서 로그인 → 가족 참여까지 한 번 통과

> ℹ️ **비즈니스 앱 전환은 아마 불필요하다.** 이메일·전화번호·카톡 메시지 API를 쓸 때 필요한 것이고
> 우리는 닉네임만 쓴다. 다만 정책은 바뀌므로 콘솔에서 확인할 것.

이 앱의 리텐션은 **월 1회**다. 알림이 없으면 그냥 잊는다. 기획서에서는 v0.2로 뒀지만,

## 7. 나중에 — 스토어 출시 (Track B)

지금은 안 한다. 하게 될 때 필요한 것만 적어둔다.

### 7-1. 법적 문서 (공개 URL 필요)

- [ ] **개인정보처리방침**(필수) · 이용약관
- [ ] 수집 항목 명시: 카카오 회원번호 / 닉네임 / 프로필 이미지 URL / **사용자가 직접 입력한 가계 데이터**
- [ ] 보관 기간과 파기 절차

> ✅ **금융 라이선스(마이데이터 등)는 필요 없다.** 계좌·카드를 연동하지 않고 사용자가 직접
> 적는 구조이기 때문이다. **설계에서 얻은 이득이니 확실히 해두자.**

### 7-2. 계정 삭제 (Google Play 필수 정책)

앱 안에서의 삭제 + 웹에서 접근 가능한 삭제 요청 경로, **둘 다** 필요하다. 현재 둘 다 없다.

- [ ] `DELETE /me`
- [ ] **정책 결정**: 가족장이 탈퇴하면 가족은? 남은 기록은? 다른 가족원 장부에서 그 사람 몫은?
      (지우면 과거 합계가 바뀐다 — 1-2와 같은 판단: 멤버십만 비활성, 기록은 남긴다)
- [ ] 앱 내 삭제 화면 + 웹 삭제 요청 페이지

### 7-2-1. 🔴 `READ_SMS` 를 넣기로 했다면 (기획서 1-3)

카드 내역 불러오기를 만들기로 결정했다면, **그건 스토어 심사에서 가장 위험한 항목이다.**

- [ ] **초기 출시에는 포함하지 않는다.** 실사용 이력이 쌓인 뒤 업데이트로 올린다
      → 거절돼도 **앱 전체가 아니라 그 업데이트만** 막힌다. 첫 심사에 얹으면 출시가 통째로 막힌다
- [ ] Play Console 의 **권한 선언 양식(Permissions Declaration)** 을 작성한다. 릴리스마다 다시 심사된다
- [ ] 정책 문서를 **그때 직접 확인한다** — 허용 용도 목록은 개정이 잦다
- [ ] 데모 영상 준비: **버튼을 누르는 순간에만** 읽고, 목록을 보여주고, 사용자가 고른다는 흐름
- [ ] 개인정보 처리방침에 명시: **문자 본문을 저장·전송하지 않는다** (기획서 1-5)
- [ ] 거절되면 **후퇴 경로는 없다** — 알림 리스너는 폐기했고, 그냥 손 입력으로 간다

### 7-3. 스토어 등록

- [ ] Google Play Console ($25 1회)
- [ ] **개인 개발자 계정이면: 비공개 테스트 20명 × 14일 연속**을 통과해야 프로덕션이 열린다
      (2023년 11월 이후 만든 개인 계정 대상 — 콘솔에서 본인 해당 여부 확인).
      **가족 앱으로 20명을 모으는 게 은근한 허들이니 일정에 미리 넣는다**
- [ ] AAB 빌드 + Play 앱 서명
- [ ] 스크린샷(폰 여러 사이즈) · 아이콘 · 짧은/긴 설명 · 카테고리
- [ ] **데이터 보안 양식**(Play) / **App Privacy**(Apple)
- [ ] 콘텐츠 등급 설문

## 요약 — 딱 세 가지만 고른다면

1. **요약 게이트를 없앤다.** 지금 구조는 멤버 한 명이 장부를 영원히 막는다.
2. **`DEV_LOGIN`을 끈다.** 안 끄면 이름 하나로 가족 가계부가 열린다.
3. **서버를 올리고 Postgres로 바꾼다.** 이게 없으면 앱은 껍데기다.
