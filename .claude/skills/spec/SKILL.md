# 기능 정의서 조회

**전부 읽지 않는다.** 인덱스(`docs/04-기능-정의서-인덱스.md`)로 후보를 좁힌 뒤,
필요한 페이지 **한둘만** 연다. 기능이 33개라 통째로 읽으면 매번 값을 치르게 된다.

## 인자에 따라

| 준 것 | 어떻게 찾나 |
|---|---|
| `F-ENT-04` | 인덱스에서 그 행 → Notion 링크를 연다 |
| `server/src/services/book.ts` | **파일 맨 위 `// 기능:` 주석을 먼저 본다** (늘 최신이다).<br>주석이 없으면 인덱스에서 경로로 찾고, 그래도 없으면<br>`git log --format='%(trailers:key=Feature,valueonly)' -- <경로>` |
| `family` 같은 도메인 | 인덱스의 그 절 표를 보여준다. Notion 은 열지 않는다 |
| `H3` 같은 하드룰 | 인덱스를 `H3` 로 grep 한다. 리뷰할 때 이 축으로 본다 |
| 없음 | 현재 브랜치 이름의 기능 ID |

## 함께 볼 것

- 하드룰이 걸려 있으면 **CLAUDE.md 「도메인 하드룰」의 해당 항목**을 같이 읽는다
- 기획서 절이 걸려 있으면 그것도 연다. **충돌하면 기획서가 맞다**
- 진행 상태는 Notion 에 없다 — GitHub 이슈의 열림/닫힘이 답이다

## 문서와 코드가 다르면

임의로 맞추지 않는다. CLAUDE.md 「명령이 문서와 다를 때 — 네 갈래」로 간다.
경로·이름처럼 **사실 확인으로 끝나는 것만** 고치고 보고하고, 나머지는 근거를 대고 묻는다.
