# 달살림 MVP 출시 체크리스트

> 이 문서에서 말하는 **"출시"는 스토어 등록이 아니라 "우리 가족이 실제로 매달 쓰기 시작하는 것"**이다.
> 기획: `01-MVP-기획서.md`
>
> ⚠️ **이 문서는 「출시라는 사건에 무엇이 필요한가」만 답한다.** 무엇이 구현됐는지는 코드와
> GitHub 이슈가 답이고, 검증 개수는 `npm test` 가 답한다 — 여기에 개수를 세어 적지 않는다.
> 체크박스가 코드보다 낡는 것이 이 문서의 실패 방식이라, 끝난 항목은 **한 줄로 줄여** 남긴다.

## 0. MVP 출시의 정의 — 스토어는 지금 하지 않는다

| | **A. 가족 내부 배포 ← 여기까지 왔다** | **B. 스토어 공개 (나중)** |
|---|---|---|
| 배포 방법 | APK 직접 전달 / Play 내부 테스트 | Play Store · App Store 정식 등록 |
| 개인정보처리방침 | 있으면 좋음 | **필수** (공개 URL) |
| 계정 삭제 기능 | 없어도 됨 | **필수** (앱 내 + 웹 링크) |
| 스토어 등록정보·스크린샷 | 불필요 | 필수 |
| Play 비공개 테스트 20명 × 14일 | 불필요 | 개인 계정이면 필수 |
| **실작업** | 끝났다 (9장) | **+ 3~4주 (대기 포함)** |

### 왜 A만 하는가

B 항목의 대부분은 **제품을 좋게 만드는 일이 아니라 심사를 통과하는 일**이다.
그리고 이 앱은 **두 번째 달부터 진가가 드러나는 구조**다 (기획서 10장 성공 기준 5번).
석 달 써보기 전에는 스크린샷에 뭘 담아야 할지도 모른다.

> **세 달 쓰고 → 반드시 나올 불만을 고치고 → 그 다음에 스토어.**
> 그게 스크린샷을 두 번 찍지 않는 길이다.

## 1. ✅ 제품에 뚫려 있던 구멍 셋 — 전부 메웠다

기능이 없어서가 아니라 **설계상 막다른 길**이던 셋이다. 기획서 4장의 v0.1 항목 7·8·9다.

- [x] **1-1. 요약 게이트를 없앴다** — 전원 제출 전이면 `summary` 가 409 를 내던 것을 걷어냈다.
      요약은 항상 열리고 `progress`(제출 수 · 정원 · 아직 안 적은 사람)를 같이 준다.
      앱은 「○○님이 아직 안 적었어요 — 아래 숫자는 N명 기준이에요」를 띄운다.
      `MonthlyBook.status` 는 남겼지만 **잠금이 아니라 표시**다 (하드룰 7)
- [x] **1-2. 나가기 · 내보내기 · 가족장 이양** (`F-FAM-08` · `F-FAM-09`) — 나간 사람은 지우지 않고
      `status='LEFT'` 로 둔다. 지우면 그 사람이 냈던 달의 합계가 바뀐다 (하드룰 6).
      가족장은 넘기지 않고는 못 나가고, 혼자 남았으면 가족을 없애는 길로 간다 (`F-FAM-11`)
- [x] **1-3. 추이 화면** (`F-BOOK-03`) — 탭이 넷이 되고 수입 · 고정비 · 남은 돈 세 줄 + 월별 표.
      두 달째부터 보인다는 안내가 있다

> **왜 이게 제일 먼저였나** — 한 명이 앱을 안 쓰기 시작하면 그 달부터 아무도 요약을 못 봤고(1-1),
> 잘못 초대한 사람을 뺄 방법이 없었고(1-2), 엑셀 대비 이기는 지점인 추이가 없었다(1-3).
> **세 달만 써도 반드시 부딪히는 것들**이라 기능 추가보다 앞에 뒀다.

## 2. 보안

### 2-1. `DEV_LOGIN` 차단 (치명적) — ✅ 코드로 막음

```
POST /auth/dev { "name": "아빠" }  →  토큰 발급
```

**이름만 알면 아무나 그 사람이 된다.**

- [x] 기본값을 **꺼짐**으로 바꿨다 — `.env`에 `DEV_LOGIN=true`를 직접 적어야만 켜진다
- [x] `NODE_ENV=production`이면 켤 수도 없고, `/auth/dev` **라우트를 아예 등록하지 않는다**
      (환경변수 실수 하나로 뚫리는 구조를 남기지 않는다. 핸들러 안에도 검사가 한 겹 더 있다)
- [x] 앱의 개발용 로그인 UI는 `/auth/config`를 따라 자동으로 사라진다

⚠️ **배포할 때마다 다시 본다** — `GET /health` 의 `devLogin` 이 `false` 인지, `sha` 가 방금 배포한
커밋인지. 되풀이되는 확인이라 체크박스로 두지 않는다. `[x]` 로 닫아두면 다음 배포 때 아무도 안 본다.

### 2-2. `JWT_SECRET` 실제 값으로 — ✅ 코드로 막음

기본값 `dalsalim-dev-secret-change-me`가 알려지면 **아무 사용자로도 위조 가능**하다.

- [x] 운영에서 기본값이면 **서버가 아예 뜨지 않는다** (조용히 도는 것보다 안 뜨는 게 낫다)
- [x] 랜덤 값으로 교체 (`openssl rand -base64 32`)
- [x] 저장소에 커밋하지 않는다 — `.env` 는 `.gitignore` 에 있고, 커밋 훅의 비밀 스캔이 한 겹 더 막는다

### 2-3. HTTPS — ✅ Railway 가 준다

- [x] 토큰이 평문으로 다니지 않는다 — 운영 주소가 `https` 다
- [x] 카카오 Redirect URI 도 그 주소를 쓴다 (카카오가 운영에서 https 를 요구한다)

### 2-4. 레이트리밋 — ✅ 적용

- [x] `@fastify/rate-limit` 추가. 전역 분당 300회,
      키는 로그인했으면 사용자 id, 아니면 IP (한 집에서 공유기를 같이 쓰므로 IP 로만 묶으면 서로 갉아먹는다)
- [x] `POST /families/join` 분당 10회 — 초대코드 무작위 대입 차단
- [x] `POST /auth/kakao/*` 분당 10회

### 2-5. 초대코드만으로는 못 들어온다 — ✅ 승인 구조

초대코드는 카톡으로 오가는 문자열이라 언제든 새어나갈 수 있다. 그것 하나로 남의 가계부가 열리면 안 된다.

- [x] 코드를 맞혀도 `PENDING`(승인 대기)으로 들어간다. 가족장이 승인해야 `ACTIVE`가 된다
- [x] `PENDING`은 가계부를 한 줄도 못 보고, 장부 정원("전원 제출")에도 안 들어간다
- [x] 내보낸 사람이 코드로 되돌아오는 것도 막힌다 — 재참여도 다시 승인을 받는다
- [x] 가족장은 [가족] 탭에서 승인/거절한다. 요청이 있으면 [이번 달] 홈에도 뜬다
      (참여 요청 알림이 없어서, 안 알려주면 요청이 들어온 줄 모른다)
- [ ] **참여 요청** 알림이 붙으면 홈 안내는 보조 수단으로 물러난다.
      정산일 알림(`F-FAM-10`)은 붙었지만 이건 아직 없다 — 요청이 온 줄 모르는 문제는 그대로다

## 3. 서버를 세상에 올리기 — ✅ 올라갔다 · 🔴 **백업은 남았다**

Railway 에 올라가 있고 Postgres 를 본다. `https://dalsalim-production.up.railway.app`
실제로 걸린 함정 셋은 `README.md` 「배포 (Railway)」 4절에 적어뒀다.

- [x] 호스팅 — Railway. 서버와 Postgres 를 한 프로젝트에 둔다
- [x] **SQLite → PostgreSQL** — 배포 직전에 옮겼다. 로컬 개발도 Postgres 를 본다
- [x] **마이그레이션 체계로 전환** — `prisma migrate deploy` 가 `start` 에 걸려 있다.
      `prisma db push` 는 쓰지 않는다
- [x] `PUBLIC_BASE_URL` 을 실제 도메인으로 — 안 채우면 `redirect_uri` 가 `localhost` 로 만들어져
      카카오가 거절한다
- [x] `HOST=0.0.0.0` (기본값) · `PORT` 는 도메인의 target port 와 같게 넣는다
- [ ] 🔴 **백업 — 미뤘다가 방아쇠가 당겨졌다.** Railway 자동 백업이 유료라 「테스트 데이터뿐일 때는
      값어치가 낮다」로 넘겼는데(2026-09-07 결정), 그 결정에 달아둔 방아쇠가
      **「가족이 진짜로 한 달을 적기 시작하면」** 이었다. APK 를 나눠줬으니 지금부터가 그때다.
      날아가면 복구 수단이 없다 — 무료 티어 정책이 바뀌거나 마이그레이션을 한 번 잘못하면 간다.
      무료 대안은 `cd server && npm run db:export` 로 덤프를 떠두는 것이고,
      **정할 것은 「언제 돌리나」** 다 (자동화해서 저장소에 올리면 안 된다 — PUBLIC 저장소다)
- [x] 앱의 `EXPO_PUBLIC_API_URL` 을 운영 주소로 (**빌드 시점에 박힌다**)

      (지우면 과거 합계가 바뀐다 — 1-2와 같은 판단: 멤버십만 비활성, 기록은 남긴다)

### 7-2-1. 🔴 `READ_SMS` 를 넣기로 했다면 (기획서 1-3)

카드 내역 불러오기를 만들기로 결정했다면, **그건 스토어 심사에서 가장 위험한 항목이다.**

- [ ] **초기 출시에는 포함하지 않는다.** 실사용 이력이 쌓인 뒤 업데이트로 올린다
      → 거절돼도 **앱 전체가 아니라 그 업데이트만** 막힌다. 첫 심사에 얹으면 출시가 통째로 막힌다
- [ ] Play Console 의 **권한 선언 양식(Permissions Declaration)** 을 작성한다. 릴리스마다 다시 심사된다
- [ ] 정책 문서를 **그때 직접 확인한다** — 허용 용도 목록은 개정이 잦다
- [ ] 데모 영상 준비: **버튼을 누르는 순간에만** 읽고, 목록을 보여주고, 사용자가 고른다는 흐름
- [ ] 개인정보 처리방침에 명시: **문자 본문을 저장·전송하지 않는다** (기획서 1-5)
- [ ] 거절되면 **후퇴 경로는 없다** — 알림 리스너는 폐기했고, 그냥 손 입력으로 간다
